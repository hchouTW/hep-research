# hep-theory

Use when the deliverable is a theoretical or phenomenological result: model definition and conventions (units, metric, couplings, schemes, scales), symbolic or analytic derivations, amplitudes, cross sections, decay rates and widths, whether a process or diagram is allowed, approximations and validity domains, theory uncertainties (scale envelopes, truncation, PDFs, model alternatives), event-generation physics, SMEFT conventions, consistency checks, predictions for comparing a model with published data, and recasting a published analysis. Works with no experiment.

**Owns:** models, assumptions, conventions, derivations, predictions, event-generation physics, approximations, validity, theory-uncertainty prescriptions, consistency checks; definitions of units, constants and generic kinematics. Typical artifacts: `theory-spec` (with a Markdown derivation record carrying a JSON header) and `prediction` (JSON plus CSV for grids, explicit units).

**Never:** require experiment, detector, data or blinding fields; claim support for a domain because a tool ran; report numerical agreement as proof.

## Scripts

`dis_kinematics.py` (invariants, beam relations, Jacobians, frames; lepton-mass bounds), `pdf_uncertainty.py` (`+as` alpha_s members, `num_members`), `event_weights.py` (signed weights pass unclipped; selected-event statistics), `eft_truncation.py` (cross-term convention, rescaling check), `physical_data.py` (constants, particle and nuclide data, unit conversions and decay Q values from `core/constants`, each with value, uncertainty, unit, source and edition: CODATA 2022, a PDG 2026 subset, AME2020/NUBASE2020; full tables through user-supplied AME/NUBASE files or the optional `pdg` package), `kinematics.py` (two-body decays via the Kallen function, Lorentz boosts, invariant masses, Mandelstam variables, fixed-target thresholds, Dalitz boundaries, rapidity and pseudorapidity, width/lifetime/c tau; masses as numbers or bundled particle names; over `core/kinematics/fourvector.py`), `import_published_table.py` (a user-downloaded CSV, FITS or HEPData table with declared columns, units, edges and uncertainty breakdown to a dataset-record labelled user-supplied, with a provenance sidecar: sha256, URL, download date, citation request; the breakdown is checked against a declared total; no network access), `neutrino_oscillation.py` (three-flavour probabilities in vacuum and constant-density matter, PMNS in the PDG convention, neutrino or antineutrino; every parameter is an input and the conventions block travels with the result), `running_coupling.py` (alpha_s in MS-bar at 1-4 loops with heavy-quark threshold matching, from a stated alpha_s(m_Z) and quark masses; stops where alpha_s > 0.5). `references/particle-physics-essentials.md` is the entry page for widths and lifetimes, Breit-Wigner forms, CKM and PMNS conventions and PDG particle codes. `decay_chain.py` gives the amounts and activities of a decay chain (Bateman for linear chains, a matrix exponential for branches, production or nearly equal constants; NUBASE2020 half-lives with their edition), `lepton_energy_losses.py` gives synchrotron and inverse-Compton loss rates of electrons with Thomson or Klein-Nishina factors, the loss time and the diffusion distance, `dm_direct_rate.py` gives the spin-independent recoil rate in the standard halo model with the Helm form factor, J and D factors and indirect-detection flux prefactors (every halo and cross-section input from the user), `coalescence.py` converts between the coalescence momentum p0 and B_A, builds a coalesced invariant yield and gives the Wigner-function weights, `secondary_gamma.py` gives gamma rays from a pi0 spectrum (exact kinematics), neutrino flavour ratios after averaged oscillations and head-on thresholds on a target photon, `bartels_rotation.py` converts dates and Bartels rotation numbers (27-day rotations from 1832-02-08) and averages a daily heliospheric input over each rotation with a declared lag and minimum coverage, `references/cosmic-ray-phenomenology.md` is the second propagation page (codes, cross-section sets and nuisances, global fits) and links `solar-modulation-models.md` and `cosmic-ray-new-physics.md`, `references/astroparticle-essentials.md` is the astroparticle entry page, and `references/nuclear-physics-essentials.md` is the nuclear entry page (atomic vs nuclear masses, Q values, decay laws, radii, the S factor). Each refuses non-finite or ambiguous input with exit 1 and a JSON reason. The SymPy interpreter for derivations is chosen by `skills/hep-computing/scripts/find_python.py` (Python 3.13 or newer). A HEPData table becomes a dataset record through `adapters/hepdata/assets/hepdata_record.py`. Compiled cosmic-ray data from CRDB (LPSC) come through the optional `adapters/crdb/assets/crdb_query.py` (`tested-in-declared-environment`, CRDB V4.2): a secondary source, so HEPData or the paper's tables stay primary and a CRDB value is a cross-check or a fallback labelled secondary; the experiment filter has no default and every row is labelled secondary. Cosmic-ray kinematics (rigidity, momentum, total and kinetic energy, kinetic energy per nucleon, bin edges and flux Jacobians) is `core/kinematics/relativistic.py` (steward hep-theory), and force-field solar modulation is `skills/hep-measurement/scripts/solar_modulation_force_field.py` (its derivation, validity range and a power-law closed-form benchmark are in a theory-domain profile listed in `profiles/registry.json`); `references/cosmic-ray-propagation.md` states their conventions. A user's own computer algebra system (Mathematica, FORM, Maple, ...) may be used for a derivation; its name, version and input files are recorded in the computational-run (`<plugin root>/skills/hep-computing/scripts/environment_manifest.py record --inputs ...`) so the derivation can be rerun.

## References

`references/mathematical-reasoning-and-proof.md` gives the proof-status ladder (formal, analytic, perturbative, asymptotic, heuristic, numerical, empirical, conjecture, not derived) that every derivation record states; the other files are topic references. Shipped theory-domain profiles are listed in `profiles/registry.json`. Outside v1 (lattice QCD and its global analyses, EFT global fits, global cosmic-ray propagation fits that run a propagation code), the skill says what it cannot cover.

## How this folder is used

`SKILL.md` is the entry point the host loads (its front matter carries the description that routes a request here; it
stays under 8 KiB). This README is for people browsing the folder. The skill reads the project's profiles only
through the context-resolution steps in `SKILL.md`; it never embeds experiment facts, and durable results are written
as JSON artifacts in the project's `artifacts_dir`, never inside the plugin. Scripts take `--help` and are standard
library first; a successful run is a software check, not scientific validity.
