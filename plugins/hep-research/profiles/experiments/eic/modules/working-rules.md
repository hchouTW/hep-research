# Working rules: EIC profile

> Method owner: none (profile scope and labels); general methods belong to the skills named in [the placement inventory](placement-inventory.md).

- **Two scopes, never merged.** "EIC" names the facility (beams, polarization, interaction regions). "ePIC" names one experiment, the first at the EIC. A sentence about ePIC says "ePIC"; a sentence about the facility says "EIC". Do not write "the EIC detector".
- **Labels.** Every number is one of: requirement or design target (facility or project document), design value (an ePIC construction parameter), proposal (a run plan proposed by ePIC), simulation projection, test-beam result, measurement. Modules quote only the first three and proposals, the four `scope.number_kind` values `requirement`, `design-target`, `design-value` and `proposal`, and each numeric claim's `scope.text` says which ([source policy](sources/source-policy.md)). Never call a projection or a design value "measured". The ledger also holds claims added for `reference:geometry-cases` (eic:C10 to eic:C37, with the geometry release eic:S10), among them prototype and predecessor designs and one performance number; they carry no `number_kind`, and no module quotes their numbers.
- **Nothing from memory.** A statement about the EIC or ePIC appears in a module only with a claim id (`eic:C01`) whose source was read at the stated level on the stated date. A source published after a claim's verification date is unverified, not nonexistent.
- **Unknown stays unknown.** Beam-direction sign, polarization sign conventions, geometry release, data-format version and every performance number are `unknown` until the user or a cited release states them. Never fill them with a plausible value.
- **Ask before selecting.** A detector question that names the EIC but not the detector concept, geometry release and configuration (energies, species) asks for them. Do not pick ePIC silently; do not pick a configuration silently.
- **General methods live with their owners.** DIS kinematics and QCD (hep-theory), selection and corrections (hep-measurement), tracking, calorimetry and PID methods (hep-detector), likelihoods and unfolding (hep-statistics), code and software environments (hep-computing). This profile adds EIC or ePIC application only, with a link to the owner.
- **Project material stays in the project.** Cuts, samples, campaign settings, private conditions, unpublished constants go in `hep-research.project.json`, a local profile or research artifacts, never here; non-public items reach the agent only where the project's `agent_policy` allows them on a qualified host configuration (none is qualified yet).
- **No software is run.** eic-shell, EICrecon, the epic geometry and EDM4eic are documented entry points; nothing here installs, builds or executes them. No module pins a software or geometry release: the one release in the ledger (eic:S10) is cited only by the geometry-case claims.
- **The prohibited phrase.** The phrase that the first rule forbids appears only inside quoted record text: the authors of eic:S04, the meeting named in the date note of eic:S16, their rows of the generated evidence index, and one exclusion in `profile.json`. Matching is case-insensitive; write it nowhere else.
