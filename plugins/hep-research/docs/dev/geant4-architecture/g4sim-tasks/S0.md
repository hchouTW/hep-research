# g4sim phase S0: Decisions and documents

## Background

Phase S0 of the g4sim plan (Part B of `docs/dev/geant4-architecture/g4sim-task.md`, Section 19.2). Labels S0-S9, T1, T2 and GB1-GB24 are local to that plan (Section 1).

This card uses the headings `lint_task.py` requires, and carries the eight sections of Section E5, in E5's order, as level-4 headings under them: Goal, Scope checklist, Deliverables, To-verify list, Thresholds and test designs, Environments, Risks and stop points, Execution log.

Pre-registration (Section 19.2): this card is fixed by its SHA-256 in `docs/dev/geant4-architecture/g4sim-task-registry.json` before any run a threshold judges. Thresholds may be tightened, never loosened. An entry that only appends to the Execution log is registered again with that reason, so the thresholds keep their earlier registration.

Documents copied unchanged from the task package: `docs/dev/geant4-architecture/g4sim-task.md`, SHA-256 `d41e012854bd21b2d7e52ec7d78dae6e0b7d6c06e78b9b86244ad960ba05934b`; `docs/dev/geant4-architecture/g4sim-task.zh.md`, SHA-256 `d5ff764651d4d77d649f153310745f633aa2a063baf5a68eab120fdca2f0c241`.

## Technical Approach

1. Work in worktree `../hep-research-g4sim-S0` on branch `g4sim/S0`, and verify it before every session (Section E2).
2. Copy the two documents byte for byte and compare hashes with `MANIFEST.sha256`.
3. Generate the verbatim scope of each card from Part B and add the phase-specific rules by hand; never invent a value that Part B leaves to a later trial run.
4. Commit each card, compute its SHA-256, then record it in the registry and commit the registry (Section E4, step 4).
5. Prepare the approval packet with every approval field empty, then stop.
6. Evaluate every gate exactly as registered. On a failed gate, stop and report; never loosen a threshold or redesign to pass (Section E4, step 8).
