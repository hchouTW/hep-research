# g4sim phase S1: Identities, specifications, geometry foundations and the translator

## Background

Phase S1 of the g4sim plan (Part B of `docs/dev/geant4-architecture/g4sim-task.md`, Section 19.2). Labels S0-S9, T1, T2 and GB1-GB24 are local to that plan (Section 1).

This card uses the headings `lint_task.py` requires, and carries the eight sections of Section E5, in E5's order, as level-4 headings under them: Goal, Scope checklist, Deliverables, To-verify list, Thresholds and test designs, Environments, Risks and stop points, Execution log.

Pre-registration (Section 19.2): this card is fixed by its SHA-256 in `docs/dev/geant4-architecture/g4sim-task-registry.json` before any run a threshold judges. Thresholds may be tightened, never loosened. An entry that only appends to the Execution log is registered again with that reason, so the thresholds keep their earlier registration.

## Objective

#### Goal

Deliver the identity and geometry foundations: `core/canonical`, `core/geometry` with box placements, the four new schemas and `contracts/geometry.py`, the run-card schema, the translator with its legacy block, ProbeV2, the inventory table with its re-acquisition builds and reproduction checks, and the performance budget (Section 19.2, S1).

**This phase's negative tests (Section 15.1)**

- [ ] Specification: Schema, units, `params`, coordinate frames, claim resolution. Negative test: An illegal combination; an unresolvable claim
- [ ] Specification: Reading procedure: normalization by schema type; different forms of a quantity field give the same string; hashing only after normalization. Negative test: `53` and `53.0` in a quantity field must give the same hash; `6.5` in an integer field must be rejected; a Decimal handed straight to hashing, bypassing the reading procedure, must be rejected by `check_hash_scope`
- [ ] Specification: Bitfield: copy-number fields ≤ 31 bits, virtual-segmentation fields ≤ 53 bits (all S1 placements are single-index). Negative test: A 32-bit copy-number field; a 55-bit segmentation field
- [ ] IR: Gap rule and containment (exact decimal; box placements). Negative test: (1) Two faces 1.1×10⁻⁷ mm apart must be an error; (2) a daughter face 1×10⁻⁷ mm outside its mother must be an error
- [ ] IR: Template dimensions independent of position. Negative test: The same template placed at different positions must give the same solid
- [ ] IR: Double-precision error bound B ≤ 1×10⁻¹⁰ mm (S1 has only translations and rotations by multiples of 90 degrees, kᵢ = 1); minimum feature; rotations that are not multiples of 90 degrees are always rejected before S3. Negative test: A placement at coordinate 1×10⁶ mm; below the minimum feature; a `single` placement rotated by 30° must be rejected in S1
- [ ] IR: cellIDs unique with enough bits; volume IDs unique, total width ≤ 64 bits, strides ≤ 2⁵³ − 1. Negative test: One bit too few; two placement levels sharing a stride; a placement chain whose level widths total 65 bits
- [ ] IR: Region and field actually belonged to (written into the IR from S1); conflicts (including field vs no field) rejected. Negative test: The same template placed in a mother with a field and a mother without; the same template falling into different regions through two mothers
- [ ] IR: Material budget (computed analytically along rays). Negative test: One layer's material swapped
- [ ] Identity: Changing `frames` changes `geometry_id`; changing only tags with the same selected objects changes neither identity; changing tags so that a physics requirement's selection changes changes `geometry_id`; so that a scorer's selection changes changes `request_id`. Negative test: Putting tags into the physical part; writing a physics requirement into the physical part as tags (instead of an expanded list)
- [ ] Translation: The legacy block, taken from the old program's write-back, round-trips to the original file. Negative test: Changing one position by 1 ulp
- [ ] Translation: Inventory table: every recorded run belongs to exactly one of the four classes of Section 7.4, with the comparison scope recorded. Negative test: A run left unclassified; a summary-only run marked as covering the column file; a reproduction check of a re-acquisition build using a different seed
- [ ] Translation: Reproduction check of the re-acquisition build: output bit-identical to the reference output; existing probe record agrees with the re-acquisition record; regenerated baseline agrees with the comparable values of the run record. Negative test: One extra random-number call in the re-acquisition build must make the reproduction check fail; changing an existing probe record by 1 ulp must make the agreement check fail
- [ ] canonical: `core/canonical` and the three unmodified implementations are byte-identical on a fixed input set; provider point hash unchanged. Negative test: Changing the separator of one of the implementations

#### Thresholds and test designs

**Gates, verbatim from Section 19.2**

1. All committed hashes recompute identically: release manifest, revocation fixtures, detsim plans and detsim run_ids, provider point hashes.
2. The equivalence tests pass.
3. All detector-simulation tests pass.
4. Every recorded old specification round-trips through the translator to the original file; the legacy block of every T1-class run equals the re-acquisition build's ProbeV2 record (Section 7.4).
5. The inventory table covers every recorded run listed in GL2, each run belonging to exactly one of the four classes of Section 7.4, with reasons and comparison scope. Every T1-class run's legacy block (`source: probe`) corresponds to a re-acquisition record that passed the reproduction check, with the probe reporting an unchanged random-number state; every T2-class run's legacy block (`source: translated`) has passed the translator round-trip check, with the reason it is T2 recorded.
6. Golden files give the same `geometry_id` on E2 and E5.
7. This phase's negative tests.
8. This phase's prototype gates (GB1, GB2, GB4, GB10, GB22).
9. `check_layering.py` (including steward checks) passes.
10. G5 confirmation of `ProbeV2.hh` and the prototype test programs for GB1, GB2, GB4, GB10, GB22.
11. Entry-point tests under protected mode for `contracts/geometry.py`, added by the custodian's answer of 2026-11-05 (Section 22; `g4sim-approvals.md`). This adds a gate and loosens none.

**Phase-specific values and rules**

- Hash gates are exact equality; there is no tolerance (gate 1).
- Numerics (Q1): 34 significant digits, round-half-even; ε = 1×10⁻²⁰ mm; c = 1×10⁻⁶ mm; B ≤ 1×10⁻¹⁰ mm.
- Bitfields (D2): copy-number fields ≤ 31 bits; virtual-segmentation fields ≤ 53 bits; volume-ID widths ≤ 64 bits; strides ≤ 2⁵³ − 1.
- GB10 chains: X = 2×10⁴ mm, translation only with d = 26, arbitrary rotation on every level with d = 2.
- Rule, fixed at this card's refresh and before the first re-acquisition build: the computational cost of the reruns is estimated here (Section 7.4).
- Rerun cost: not yet estimated. The recorded runs hold no wall-clock times, so the estimate needs a timed sample on E2, and it is registered here before the first re-acquisition build. Scope known so far: 110 Geant4 runs (J14 26, J15 74, J16 10) plus the TestEm3 and TestEm5 mirrors.
- Rule: the performance budget's numbers (Section 16) are written in S1 and registered before any S2 run they judge.

**Prototype criteria, verbatim defaults from Section 23**

- GB1: For the geometries of both old programs, read the doubles of `G4PhysicalVolumeStore` directly with a test hook and compare bit by bit with the probe's `float.hex()` record, with 0 disagreements; compare the random-number state before and after the probe with `G4Random::saveFullState`, which must be the same; running only `/run/initialize` writes `recorded: false`, and with `/run/beamOn 0` the probe does not run
- GB2: The reproduction check of Section 7.4, executed run by run. The only consequence of falsification is that the run is reclassified as T2; it does not trigger a design change
- GB4: A geometry with three levels of nesting and two regions; the region name written back for each logical equals the IR
- GB10: Read out the run-time tolerance; build two placement chains at X = 2×10⁴ mm (translation only, d = 26; arbitrary rotation on every level, d = 2), with two faces c apart at the end of each chain: the measured errors of sampled points transformed through all levels are all ≤ the B of Section 7.3; a geantino crossing each gap in turn has a number of steps equal to the expected number of volume crossings, with no stuck tracks
- GB22: Run a re-acquisition build built for MT once: the probe runs on the master, and no logical's field record is `declared` (the marker of `geant4-program.md` §A2.4). Runs for which this does not hold cannot reproduce the field assignment with T1: the inventory table lists them as T2 (`source: translated`, with fields determined by the old specification), with the reason recorded
