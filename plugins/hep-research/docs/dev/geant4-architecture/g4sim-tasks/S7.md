# g4sim phase S7: Optics, transition radiation and the remaining shapes

## Background

Phase S7 of the g4sim plan (Part B of `docs/dev/geant4-architecture/g4sim-task.md`, Section 19.2). Labels S0-S9, T1, T2 and GB1-GB24 are local to that plan (Section 1).

This card uses the headings `lint_task.py` requires, and carries the eight sections of Section E5, in E5's order, as level-4 headings under them: Goal, Scope checklist, Deliverables, To-verify list, Thresholds and test designs, Environments, Risks and stop points, Execution log.

Pre-registration (Section 19.2): this card is fixed by its SHA-256 in `docs/dev/geant4-architecture/g4sim-task-registry.json` before any run a threshold judges. Thresholds may be tightened, never loosened. An entry that only appends to the Execution log is registered again with that reason, so the thresholds keep their earlier registration.

#### Thresholds and test designs

**Gates, verbatim from Section 19.2**

1. The escape fraction of a simple block is equivalent to the analytic value: TOST, α = 0.05, margin ±1% (relative), power 0.9, sample size derived from this.
2. The Cherenkov angle is equivalent to cos θ = 1/(nβ): TOST, α = 0.05, margin ±0.5 mrad, power 0.9, sample size derived from this.
3. TR yield vs sourced data: for each data point, a TOST decides whether the relative difference lies within the relative margin Δ fixed in advance in the task card (α = 0.05); joint power ≥ 0.9 per Section 18 (K being the number of points included). Point-wise power is limited by the data uncertainty and cannot be raised by more events, so only points satisfying Δ ≥ (z_α + z_{(1+π)/2})·σ_c are included in the equivalence criterion, where σ_c combines the data uncertainty and the simulation's statistical error and π = 0.9^(1/K); points that do not satisfy it are listed for information only. The number of simulated events is such that every included point satisfies this condition. If no point can be included, gate 3 is recorded as a gap and S7 is marked partially complete.
4. Efficiency-map validation run: the mean and width of the number of photoelectrons, tested by a joint TOST; power computed per Section 18; the validation run satisfies the conditions of Section 10.4. Default margins: mean number of photoelectrons ±1%, width ±5% (relative), α = 0.05; the TOST standard error includes the statistical error of the efficiency map itself (the variance between Dirichlet replicas, which does not shrink with the number of validation events); joint power ≥ 0.9 per Section 18, with the number of events derived from this. If the efficiency-map error alone already keeps the power below 0.9, first increase the number of photons in the mapping run; the margins are not relaxed.
5. This phase's negative tests.
6. G5 confirmation of the builders for optics, XTR, field maps and the new shapes, the extension of ProbeV2, and the handling of optical photons by `KillProcess`.

**Phase-specific values and rules**

- Rule: the event counts of gates 1, 2 and 4 are derived from the stated margins and power and written here before the test.
- Rule: gate 3's Δ and the included points are written here before execution. Margins are never relaxed; gate 4 raises the number of mapping photons instead.

  - photon_detected opens: a count per detecting volume (segmentation none), on an OpBoundary Detection at a boundary step into a scorer template; photons.csv per detection (event, scorer, volume, arrival, transit = local time, energy eV, emission point). Optical primaries get a random linear polarization; a primary photon is outside incident energy.
  - Mapping run = one photon per event, uniform over the template's box (placed once, unrotated chain), isotropic, the component's spectrum as 64 weighted energies (the request's list form). Plan's "grid point" read as uniform emission within each grid cell (the cell is what the map stores).
  - efficiency-map/1 form "mapped": bins of the production segmentation (the C++ Grid formula for a box), emitted n, detected k_c, transit histogram (50 bins), hashes (materials, surfaces, mapping run id), component, spectrum.
  - Nominal = k/n; replica r of the response pipeline takes Dirichlet replica r (Jeffreys, k+1/2), keyed by map hash, replica and bin; Gamma shape < 1 by Marsaglia-Tsang's boost. >= 100 replicas.
  - Transverse uniformity (along_axis only): chi-square homogeneity of the detected fraction over 3x3 transverse sub-cells per bin, at alpha = 0.01 / B, every expected count >= 5, else "insufficient" (a failure).
  - Digitization: mapped transit from the bin's histogram (inverse CDF on the second uniform), rise time adds an exponential from an extra group when > 0.
  - Response checks: one map per component; sharing only with identical spectra (map-shared); map spectrum = component's (map-spectrum); materials hash (map-stale); validation LY nominal, yield_relative_width off, one component. check-spec: RESOLUTIONSCALE = r, Birks declared, saturation attached and ScintillationByParticleType off as read back from Geant4 (effective-em.json "optical").
  - Cherenkov: an optical L3 case declares cherenkov_handling full_optical_tracking (a) or declared_negligible (b) with the measured fraction below the declared precision (profile convention + test).
  - Live: 60,000-photon map in 8 s, 5 bins about 2.4% each, uniformity passed (p 0.06-0.18 vs 0.002); validation-style e- run: saturation true, by-particle-type false, 89,069 photons, 2,443 detected, residual 1.5e-15.
- XTR (Section 6.2.9 rules 1-6). Decided (E7, mine):
