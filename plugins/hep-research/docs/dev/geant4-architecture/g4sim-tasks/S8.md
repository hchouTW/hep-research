# g4sim phase S8: Scale and conditional items

## Background

Phase S8 of the g4sim plan (Part B of `docs/dev/geant4-architecture/g4sim-task.md`, Section 19.2). Labels S0-S9, T1, T2 and GB1-GB24 are local to that plan (Section 1).

This card uses the headings `lint_task.py` requires, and carries the eight sections of Section E5, in E5's order, as level-4 headings under them: Goal, Scope checklist, Deliverables, To-verify list, Thresholds and test designs, Environments, Risks and stop points, Execution log.

Pre-registration (Section 19.2): this card is fixed by its SHA-256 in `docs/dev/geant4-architecture/g4sim-task-registry.json` before any run a threshold judges. Thresholds may be tightened, never loosened, except through the falsification procedure of Section 23, as addendum 11.1 did for gate 3. An entry that only appends to the Execution log is registered again with that reason, so the thresholds keep their earlier registration.

## Objective

#### Goal

Deliver logical-level checks, the run card's `placement_impl`, fast-simulation hooks, and the conditional items `g4sim_digi` and GDML import only if their conditions hold (Section 19.2, S8).

#### Thresholds and test designs

**Gates, verbatim from Section 19.2**

1. Within the 10⁶-touchable numbers of the performance budget document.
2. If `g4sim_digi` is built: judged by the determinism table of Section 10.2, continuous values are within the declared ulp tolerance; every discrete disagreement, traced along data dependencies, has as its root a draw within a decision boundary; the number of affected sub-streams is reported.
3. A run with no `fast_sim_envelope` attaches no fast-simulation process. With a fast-simulation model attached that never triggers, the mean deposit of each observable is equivalent to having no hook, not bit-identical: with the same seeds, a paired TOST on the per-event differences of each observable, grouped as in S3 gate 3, α = 0.05, margin ln 1.005 of the mean, passing only if all pass, with the number of events and the power derived in the S8 task card under Section 18. In the S3 prototype, with the process attached to all particles, `G4FastSimulationManagerProcess` changed about 1% of histories (GB19); with a test model attached that kills particles at the envelope entrance and books their energy as deposit, the total deposit inside the envelope equals the incident energy (tolerance as in the closure check of Section 9.1).
4. This phase's negative tests.
5. G5 confirmation of the fast-simulation hooks, the builder of `placement_impl` and (if built) `g4sim_digi`.

**Phase-specific values and rules**

- Gate 1: the 10⁶-touchable numbers of the performance budget of S1.
- Gate 3: paired equivalence with a never-triggering model (addendum 11.1); closure tolerance of Section 9.1 with the test model.
- Rule: if `g4sim_digi` is built, the ulp tolerance is declared here before comparison (Section 10.2).
