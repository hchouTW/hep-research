## Gate 8 and the independent reads

Three versions of this gate were not sound, and none of their passes stands. At `28cfefa7` a reader changed `KeptAncestor` to always return track 1, and the check still passed. At `08e870ce` a second reader built a mutant with several wrong values, and it passed: it checked keys, not values. At `7c5e5c65` a third reader zeroed tracker kinematics, crossing energy and time, disabled `decay_products` and split deposits equally, and it passed: closure cannot see a fault that hits and scorers share, and the controls covered only the faults already found. All findings were fixed, by the maintainer's decisions (`g4sim-approvals.md`).

The gate now holds a table of every written column and the check that compares it with something independent of the file. It fails if a column has no entry, and closure against the scorers does not count. Each event runs with the rules under test and again with every track kept, from one seed. A proton tilted up and a pion tilted down, segmented tracker and calorimeter hits, event numbers above 2³¹, and a reference plane in vacuum, where a crossing is exact.

Weaker checks, as they are: `tracker_points` and `block_points` only bound a position within its volume; a secondary's vertex is checked only for decay products; `contributions` ties a calorimeter hit's `edep_MeV` to its contributions, and those to the ancestry run, which shares the same code; `cell` is checked against the volume, not an encoding.

`moments` against `column`: the same doubles, cell by cell. One thread against two: all five ntuples and `moments.csv` identical. Cells above 2⁶³: exact. A rule with a region: 41 of 41 secondaries born in it.

`split_edges.py`, live: a track on a grid's exact diagonal gives finite rows, and a track across the axis of a polar segmentation stays in its rings; the previous build fails both, with NaN rows and 116 rows out of their ring. A segmentation over 2¹⁶ bins stops the run in preflight with its reason, even a scorer nothing reaches.

## Gate 9

`element_sim` and `layered_sim` have no source change since 0.58.0, and J15 uses neither `g4sim_run` nor the new headers. The two programs J15 uses that did change were compared, old against new, built from `737fa3e6` and from this branch:

- `simroot`: `hash` and `info` on three real J15 event files, exit 0, output identical; `dump` of the crossings of 2,000 events, 25,561 lines, identical. A first comparison on the wrong file format matched only because both versions refused it, and is not counted.
- `simreco`: byte-identical on 4,000 events with J15's whole tail set on, including a fake hit reaching a fit. That file differs from the undigitized output, so the comparison reached the moved code. A first comparison with digitization off is not counted.
- `tests/examples/test_design_minimal_spectrometer.py` passes.

No full regression of the 112 runs was run at this commit.

## Open items

- Gate 11, G5. `Philox.hh`'s fsum follows CPython; the PSF licence ships as `adapters/geant4/assets/PYTHON-LICENSE.txt`. A fresh read of the changed code comes first.
- Throughput: the Python response misses the limit on low-energy workloads; the limit stands (`g4sim-performance-budget.md`). `g4sim_digi` stays an S8 conditional, undecided. `photon_times` is not in the measurement.
- `StripSigma`: too small; corrected after S4, with J15 regenerated on E2, and before any S5 reco-closure with `noise-digitization` on (`g4sim-approvals.md`).
- Deviation from Section 9.2, by the maintainer's decision: a hit's cell is its volume ID and segmentation bin. A named readout's encoded cellID is deferred to S5, and an `event_file` scorer naming one is refused.
- `simreco_strip` takes one crossing per cell and event, because a channel stream has sub-index 0 (Section 10.2); two tracks in one cell of an event are refused until encoded strip cells exist.
- Nothing outside the test scripts builds hand-off rows from hits yet.
- Polar apportioning is by 64 pieces of a step, not exact, and the outer ring takes the corners of a square volume.
- `PlaneCrossing`: a step that only touches a plane and returns is missed; a step limited by multiple scattering or ionisation in a field is treated as a chord, and a Transportation-ended step scattered by msc as a curve. The effect is small and was not measured in a field with material.
- The `cellID` mask of Section 6.3 is not part of `request_id`, because no encoded cellID exists yet.
- No geometry here has a volume ID above 2⁵³: such a cell is proved by the `high_cells` control and by `test_g4sim_external.py`, not by a real detector. The JSON hand-off holds doubles, so `simreco_strip` refuses a cell of 2⁵³ or more.
- The wiring from `Score` to the `edep_visible_ly_split` control is not tested live: no step lands on exactly μ_s = 10.
- HepMC3 reading is not implemented: it is not installed here, and check-spec refuses it; text event files are the `external` format delivered.
- No real Garfield++ table was read; the parser is tied to the writer's source by a test.
- The Philox key derivation is in `rng.py`, not `seeds.py` as Section 19.2's file table says. The IR's field set is unchanged: the scintillation block reaches the run through the request.
- `simreco_strip` does not make noise hits, which belong to no crossing.
- Earlier limits stand: `HitColumns.hh` is not in `SIM_SOURCES`; references read at metadata level; the exhaustion bound's acceptance floor is an assumption; a pure-EM residual of 5e-5 MeV has no known cause; the thin-layer PAI comparison was not run; GB13, GB20 and GB21 untested on arm64.
