# Detector reconstruction plan v9.2: coverage inventory (T01)

Base: commit `580dc79e83abbc33b27c69633d9e15658f4f90b6`, plugin 0.56.0, contracts 3.19.0, `adapters/geant4` 0.7.0, `adapters/detector-simulation` 0.5.0. Read-only inventory: nothing was run for it. Paths are relative to `plugins/hep-research/`; a bare `name.md#anchor` is under `skills/hep-detector/references/`. Old-index IDs are written `old:F4` (R09).

Reading the columns (R09: six evidence kinds, each yes, no or unprobed; no overall verdict):

- **Documentation:** `yes` only when every variant named in the row has text with its assumptions or failure modes. Otherwise `no`; `no; partly` says what exists. A documented parent family does not cover a missing variant.
- **Tool integration:** `yes` when a script, adapter or tool contract implements the task on detector observations. Scope limits are stated in the cell: F01, F11 and F16 rest on simreco, which reads simulated events only.
- **Local execution:** `yes` means a recorded run at the cited version, labelled synthetic or toy where it is. None was rerun at this baseline or on this host. Toys are never production.
- **Simulation quality:** `no` with an adjacent record means something was measured, but it does not establish reconstruction quality.
- **Data control, platform:** `unprobed` for all 38 rows. Unprobed means unavailable (R02).
- `docs/capability-map.json` keeps its own states; these columns are not a new status vocabulary.

**Corrected 2026-11-06 after T11's first pass (t11-cells.md).** The 12 families first marked `yes` are now `no; partly`, so no family has full documentation.
