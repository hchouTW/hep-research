# Capability map

One row per capability: the skill that owns it, its state today and whether it is in v1. The source is
[`capability-map.json`](capability-map.json); the table below is generated from it by `python3 tools/capability_map.py
--write`, and `--check` (run by the tests) fails when the table is stale.

- **State:** `tool` = a shipped script or core module does it; `documentation` = only guidance exists; `none` = absent.
  The state says what exists, not that it is validated; validation status is in the [capability matrix](capability-matrix.md).
- **In v1:** `no` marks a domain outside v1. Its closest owner answers with the limited-support notice ("no validated
  domain profile", stanza step 4), and `tools/check_routing_static.py` requires each such domain to name at least one
  limited-support routing case, routed to that owner (or accepted from it). A domain moves into v1 with the item named
  in "enters with".
- **Items:** the upgrade-plan items (batches A-D) that add or extend the capability.

Provenance: built for item X3 from the capability matrix, the routing contract, the seven SKILL.md files and the item
list of the upgrade work order. The plan's own 33-row map (section 3.4.1) could not be opened in the implementing
session, so this map was rebuilt rather than copied; differences from the plan's map are unreviewed.
